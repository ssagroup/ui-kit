# Field

Layout parts for building your own labelled form field around any control.
For a ready-made text field use `TextField`; `NumberField` is built from
these parts.

## Default Usage

<Description of={FieldStories.Default} />

```tsx
import { Field, Input } from '@ssa-ui-kit/core';

const Username = ({ taken }: { taken: boolean }) => (
  <Field.Root status={taken ? 'error' : 'basic'}>
    <Field.Label htmlFor="formElement-username">Username</Field.Label>
    <Field.Control>
      <Input name="username" css={{ width: '100%', border: '0 !important' }} />
    </Field.Control>
    <Field.Description>Letters, numbers and dots</Field.Description>
    <Field.Error>This username is taken</Field.Error>
  </Field.Root>
);
```

### Parts

| Part                | Renders                                       | Props                                                         |
| ------------------- | --------------------------------------------- | ------------------------------------------------------------- |
| `Field.Root`        | A `<div>` that provides the context           | `status`, `disabled`, `forwardFocus`, `asChild`, div props    |
| `Field.Label`       | The kit's `Label`, greyed when disabled       | `htmlFor`, every `Label` prop                                 |
| `Field.Control`     | The bordered box around the control           | `controlRef`, div props; children may be a function (context) |
| `Field.Description` | Helper text, only when `status` is `basic`    | `children`                                                    |
| `Field.Error`       | Error text, only when `status` is `error`     | `children`                                                    |
| `Field.Success`     | Success text, only when `status` is `success` | `children`                                                    |

`useFieldContext()` reads the same context (`status`, `disabled`,
`forwardFocus`) in your own components inside `Field.Root`.

## Live Validation

<Description of={FieldStories.LiveValidation} />

```tsx
import { useState } from 'react';
import { Field, Input } from '@ssa-ui-kit/core';

const EmailField = () => {
  const [email, setEmail] = useState('');
  const valid = /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
  return (
    <Field.Root status={email === '' ? 'basic' : valid ? 'success' : 'error'}>
      <Field.Label htmlFor="formElement-email">Email</Field.Label>
      <Field.Control>
        <Input
          name="email"
          css={{ width: '100%', border: '0 !important' }}
          inputProps={{
            value: email,
            onChange: (event) => setEmail(event.target.value),
          }}
        />
      </Field.Control>
      <Field.Error>Enter an email like name@company.com</Field.Error>
      <Field.Success>Looks good</Field.Success>
    </Field.Root>
  );
};
```

## Keyboard and Accessibility

Field adds no keyboard handling; the control inside keeps its own.

- **Link the label.** `Field.Label` renders a `<label htmlFor>`. The kit's
  `Input` and `Textarea` use the id `formElement-{name}`; for `Input`, set
  `inputProps={{ id }}` to use another id.
- **Messages are visual only.** Description, Error and Success are not linked
  to the control with `aria-describedby`, set no live-region role, and
  `status="error"` does not set `aria-invalid`.
- **Focus forwarding** (`forwardFocus`, on by default) only reaches a single
  `forwardRef` child such as `Input` or `Textarea`. For a native `<input>` or
  several children, pass `controlRef` to `Field.Control`. `controlRef` is
  focused on click even when `forwardFocus` is off.
- `disabled` on `Field.Root` only greys out the label and the control box:
  pass `disabled` to the control as well.
- `asChild` renders no wrapper, so you can use a `<fieldset>`; `className`,
  `css` and other div props on `Field.Root` are then ignored.

# DataTable

A table driven by data. Pass it rows and column definitions; it renders them,
reports sorting, and owns the column layout: widths, frozen columns, order and
hidden columns, all keyed by column id.

Use `DataTable` for interactive data tables. For a static table whose markup
you write by hand, use `Table` and its row and cell components, which
`DataTable` is built from.

Coming from `Table`'s column props or from `NestedTable`? See the
[migration guide](?path=/docs/components-datatable-migration-guide--docs).

## Default Usage

```tsx
import { DataTable, DataTableColumn } from '@ssa-ui-kit/core';

const columns: DataTableColumn<Employee>[] = [
  { id: 'name', header: 'Name', cell: (row) => row.name, sortable: true },
  { id: 'email', header: 'Email', cell: (row) => row.email },
  {
    id: 'salary',
    header: 'Salary',
    cell: (row) => formatSalary(row.salary),
    align: 'right',
  },
];

<DataTable data={employees} columns={columns} />;
```

Rows are keyed by their `id` field. Selection and expanded rows are kept as
these ids. When the id lives elsewhere, say so with `getRowId`:

```tsx
<DataTable
  data={contracts}
  columns={columns}
  getRowId={(row) => row.contractNumber}
/>
```

Rows with neither are keyed by position, and their cells remount whenever the
order changes.

`columns` does not need to be memoised. The table rebuilds its model only when
column ids or sort settings change, and always renders the latest `header` and
`cell`.

## Features

### Columns

| Field          | Description                                                                         |
| -------------- | ----------------------------------------------------------------------------------- |
| `id`           | Stable, unique id. Column state and the sort refer to columns by it.                |
| `header`       | Header content.                                                                     |
| `cell`         | `(row, rowIndex) => ReactNode`; `rowIndex` is the position as shown, after sorting. |
| `align`        | `'left'` (default), `'center'` or `'right'`, for header and body cells.             |
| `sortable`     | Clicking the header sorts by this column.                                           |
| `sortKey`      | The server's name for the column, passed to `onSortChange`. Defaults to `id`.       |
| `sortFn`       | Ascending comparator; sorts the rows in the browser.                                |
| `width`        | Starting width in pixels. Columns without one are measured on first layout.         |
| `minWidth`     | Narrowest the user can resize it to. Overrides the table's `minColumnWidth`.        |
| `maxWidth`     | Widest the user can resize it to. Overrides the table's `maxColumnWidth`.           |
| `resizable`    | `false` keeps the user from resizing it, for actions or checkbox columns.           |
| `freezable`    | `false` takes the freeze actions out of its header menu.                            |
| `reorderable`  | `false` keeps the column in place when `reorderableColumns` is on.                  |
| `hideable`     | `false` keeps the column on screen: no "Hide column", locked in the picker.         |
| `getCellProps` | `(row, rowIndex) => props` for this column's body cells; see Row and cell styles.   |

### Sorting

One column at a time. Clicking a sortable header sorts ascending, and clicking
it again toggles the direction. By default the table only reports the new sort
and expects the rows to come back sorted, which is what server data needs. The
second argument of `onSortChange` is the column's `sortKey`, ready for the
request:

```tsx
const [sort, setSort] = useState<DataTableSort | null>(null);

<DataTable
  data={rows}
  columns={columns}
  sort={sort}
  onSortChange={(next, sortKey) => {
    setSort(next);
    fetchRows({ sorting: sortKey, descending: next?.direction === 'desc' });
  }}
  isLoading={isFetching}
/>;
```

To sort in the browser instead, give the column a `sortFn`. Compare ascending;
the table reverses the result for descending:

```tsx
{ id: 'name', header: 'Name', cell: (row) => row.name, sortable: true,
  sortFn: (a, b) => a.name.localeCompare(b.name) }
```

### Column layout

`resizableColumns` lets the user drag a header's right edge, and
`freezeControls` gives each header a menu to freeze its column to either edge.
Everything the user changes lands in one `DataTableColumnState`:

```ts
{
  order: string[];                  // column ids in display order
  widths: Record<string, number>;   // px per column id
  frozen: { start: string[]; end: string[] };
  hidden: string[];                 // ids of columns not shown
}
```

Store it from `onColumnStateChange` and pass it back through
`defaultColumnState` to remember a user's layout. Pass `columnState` instead to
control it. Partial values are fine; missing parts fall back to defaults:

```tsx
<DataTable
  data={rows}
  columns={columns}
  resizableColumns
  freezeControls
  defaultColumnState={loadLayout() ?? { frozen: { start: ['name'], end: [] } }}
  onColumnStateChange={saveLayout}
/>
```

#### Resize modes

`columnResizeMode` decides what a resize does to the rest of the table:

- `fit` (default): the table keeps its width. The resizable columns to the
  right of the dragged one share the change, each in proportion to its width,
  and one that reaches its limit leaves the rest to the others. The last column
  has no handle.
- `expand`: the other columns keep their widths, and the table grows or
  shrinks and scrolls sideways.

The Column Features story puts resizing, freezing, reordering and hiding on
one table, with a switch between the two modes.

Limits apply in both modes: `minColumnWidth` and `maxColumnWidth` for the whole
table, and `minWidth` and `maxWidth` on a column for its own:

```tsx
const columns: DataTableColumn<Employee>[] = [
  { id: 'name', header: 'Name', cell: (row) => row.name, minWidth: 200 },
  { id: 'salary', header: 'Salary', cell: renderSalary, maxWidth: 220 },
  // ...
];
```

### Reordering columns

`reorderableColumns` lets the user move columns. They drag the grip that shows
at the left of a header on hover, or use "Move left" and "Move right" in the
header menu, which is the keyboard route. The new order is written to
`columnState.order`, so it is stored along with the rest of the layout:

```tsx
<DataTable
  data={rows}
  columns={columns}
  reorderableColumns
  freezeControls
  defaultColumnState={loadLayout()}
  onColumnStateChange={saveLayout}
/>
```

A column moves only among columns in the same freeze zone: those frozen to the
left, those frozen to the right, or the ones that scroll. Freezing never moves
a column, so frozen columns keep the places they stick from. A column with
`reorderable: false` keeps its place too; the others move past it, which suits
a checkbox or actions column. A column with nowhere to go, such as the only
column frozen to an edge, shows its grip faded and does not drag. Escape
cancels a drag.

### Selection

`selectionMode="multiple"` adds a checkbox column. The header checkbox selects
or clears the rows on screen, and shows a partial state when only some are
selected. `"single"` puts a radio in each row instead. The selection is a list
of row ids, so rows selected on another page stay selected:

```tsx
const [selected, setSelected] = useState<string[]>([]);

<DataTable
  data={pageRows}
  columns={columns}
  selectionMode="multiple"
  selectedRowIds={selected}
  onSelectionChange={setSelected}
  isRowSelectable={(row) => row.status !== 'Archived'}
  getRowLabel={(row) => `Select ${row.name}`}
/>;
```

`isRowSelectable` disables a row's checkbox and leaves it out of select-all.
In a tree, a row it rejects that has selectable rows below it keeps its
checkbox as a way to select them, but its own id never joins the selection.
`getRowLabel` names each checkbox for screen readers; without it, rows are
named by position ("Select row 3"). Clicking a checkbox never triggers
`onRowClick`. If the first column is frozen to the left, the selection column
stays frozen with it.

### Nested rows

`getSubRows` nests rows under rows, to any depth. Rows with children get an
expand button in a narrow column at the start, a grey background and bold
text; children are indented under them. The rows start collapsed. Pass
`defaultExpanded` (`true` for all, or a list of ids), or control it with
`expandedRowIds` and `onExpandedChange`:

```tsx
<DataTable
  data={departments}
  columns={columns}
  getSubRows={(row) => row.members}
  defaultExpanded
/>
```

Every row in the tree needs a unique id. A child with no `id` of its own, and
no `getRowId`, is keyed under its parent (`"2.0"`). A sorted column sorts each
row's children among themselves, so children always stay under their parent.
If the first column is frozen to the left, the expand column stays frozen with
it. Resizing, freezing, reordering and hiding work on nested tables as on flat
ones; the second table in the Nested Rows story shows them together.

With `selectionMode="multiple"`, selecting a row selects everything under it.
A row with only some of its children selected shows a partial check, and the
header checkbox covers collapsed rows too. The selected ids list every
selected row, parents included.

This replaces `NestedTable`: its groups become rows with `getSubRows`, and
`defaultCollapsed={false}` becomes `defaultExpanded`.

### Hiding columns

`hideableColumns` adds "Hide column" to the header menu. Hidden columns are kept
in `columnState.hidden`. To bring them back, place a `DataTableColumnPicker`
wherever the page keeps its table controls, and share a controlled column
state between the two:

```tsx
const [columnState, setColumnState] = useState<Partial<DataTableColumnState>>(
  {},
);

<DataTableColumnPicker
  columns={columns}
  columnState={columnState}
  onColumnStateChange={setColumnState}
/>
<DataTable
  data={rows}
  columns={columns}
  hideableColumns
  columnState={columnState}
  onColumnStateChange={setColumnState}
/>
```

The picker lists columns in display order. Columns with `hideable: false`
can't be cleared, and neither can the last column on screen.

### Row and cell styles

`getRowProps` on the table and `getCellProps` on a column style a body row or
cell from its data. Both return `className`, `style`, `data-*` attributes and
`background`:

```tsx
<DataTable
  data={rows}
  columns={[
    // ...
    {
      id: 'score',
      header: 'Score',
      cell: (row) => row.score,
      getCellProps: (row) => ({ background: scoreColor(row.score) }),
    },
  ]}
  getRowProps={(row) =>
    row.excluded
      ? { className: 'excluded', background: 'rgba(242, 136, 142, 0.16)' }
      : {}
  }
/>
```

Use `background` for colour rather than `style.background`. Cells paint their
own background, white, so a colour on the row element would not show; and a
frozen cell must stay opaque so the cells scrolling under it do not show
through. `background` is laid over white on every cell of the row, and over
the grey of a row with children, under the hover and selected states. On a
cell it stays on top of them.

Every row carries `data-row-id`, and a `className` from `getRowProps` lands on
the `tr`, so CSS can reach the cells as `.excluded > td`.

### Sticky header

`stickyHeader` keeps the header in view while the rows scroll. Give the table a
height limit through `maxHeight`:

```tsx
<DataTable data={rows} columns={columns} stickyHeader maxHeight={480} />
```

### Loading and empty states

`isLoading` marks the table busy. Rows already shown stay, dimmed, so a re-fetch
after sorting does not make the table jump. With no rows yet, `loadingState`
is shown; with no rows and no loading, `emptyState`:

```tsx
<DataTable
  data={rows}
  columns={columns}
  isLoading={isFetching}
  loadingState="Loading employees…"
  emptyState="No employees match these filters"
/>
```

### Row click and footer

`onRowClick` receives the row's data. Rows become focusable, and Enter on a
focused row opens it too. Clicks, and Enter, on a button, link, input or menu
inside the row are left to that control. Screen readers do not announce a row
as actionable, so when the action matters, also give the row a link or button
in a cell.

`footer` renders below the table, the place for `Pagination`:

```tsx
<DataTable
  data={pageRows}
  columns={columns}
  onRowClick={(row) => navigate(`/employees/${row.id}`)}
  footer={
    <PaginationContextProvider page={page} onPageChange={setPage}>
      <Pagination pagesCount={pagesCount} />
    </PaginationContextProvider>
  }
/>
```

# ButtonGroup

ButtonGroup is a collection of related buttons that work together as a unit for selecting between options or filtering content.

## Default Usage

A button group allows users to select one option from a set of related choices. Here's how to use it:

```tsx
import { ButtonGroup, ButtonGroupItem } from '@ssa-ui-kit/core';

const items: ButtonGroupItem[] = [
  { id: 1, text: 'All (10)', disabled: false },
  { id: 2, text: 'Running (117)', disabled: false },
  { id: 3, text: 'Stopped (2)', disabled: false },
];

function Demo() {
  const handleClick = (item: ButtonGroupItem) => {
    console.log('Selected:', item);
  };

  return <ButtonGroup items={items} onClick={handleClick} />;
}
```

## Content Modes

A button shows whatever it is given — text, an icon, or both:

```tsx
<ButtonGroup defaultValue="all" onClick={({ id }) => setSelected(id)}>
  {/* text */}
  <ButtonGroupButton id="all">All</ButtonGroupButton>

  {/* icon + text */}
  <ButtonGroupButton id="running" icon={<Icon name="clock" size={24} />}>
    Running
  </ButtonGroupButton>

  {/* icon only — square, and labelled by aria-label */}
  <ButtonGroupButton
    id="list"
    icon={<Icon name="menu" size={24} />}
    aria-label="List view"
  />
</ButtonGroup>
```

The mode follows from **which props are set**, not from what the content
renders to. An `icon` with no children is icon-only; add children and the same
icon becomes a leading icon. Passing an icon inside `children` still works, but
the group cannot tell it apart from a label and lays it out as text — use the
`icon` prop to get the square.

An icon-only button has no text for a screen reader to announce, so
`aria-label` is required. It doubles as the label the group reports through
`onClick`.

The button is a 40x40 square whatever icon size it is handed; 24px matches the
design and fills it to the intended 8px padding.

The `items` API carries the same three modes — `text`, `icon`, or both, with
`ariaLabel` in place of `aria-label`:

```tsx
const items: ButtonGroupItemInput[] = [
  {
    id: 'list',
    icon: <Icon name="menu" size={24} />,
    ariaLabel: 'List',
  },
  { id: 'columns', icon: <Icon name="dashboard" size={24} />, text: 'Columns' },
  { id: 'all', text: 'All' },
];
```

`onClick` always reports a full `ButtonGroupItem`, so handlers never have to
narrow: an icon-only item comes back with its `ariaLabel` in the `text` slot.

## Composed Usage

When a button needs markup an item cannot express, pass `ButtonGroupButton`
children instead of `items`. Selection stays on the group — each button only
declares its `id`:

```tsx
import { ButtonGroup, ButtonGroupButton, Icon } from '@ssa-ui-kit/core';

function ComposedDemo() {
  const [selected, setSelected] = useState('all');

  return (
    <ButtonGroup value={selected} onClick={({ id }) => setSelected(id)}>
      <ButtonGroupButton id="all">All</ButtonGroupButton>
      <ButtonGroupButton id="running" icon={<Icon name="clock" size={24} />}>
        Running
      </ButtonGroupButton>
      <ButtonGroupButton id="stopped" disabled>
        Stopped
      </ButtonGroupButton>
    </ButtonGroup>
  );
}
```

Two differences from the `items` API worth knowing:

- An **uncontrolled** composed group starts with nothing selected — pass
  `defaultValue` to preselect. The `items` API can default to the first item
  because it can see the list; children mode cannot.
- The group's `onClick` reports `{ id, text, disabled }` built from the clicked
  button's props. `id` is always accurate; `text` is filled in only when the
  button's content is a plain string, or its `text` / `aria-label` prop is set.
  Each button can also take its own `onClick`.

## Appearance

The group follows the PeopleOps design: a flat 40px-tall strip, 8px radius on
the outer corners only, 1px seams, `palette.secondary.light` at rest and
`palette.secondary.main` for the selected button, going one step darker on
hover and focus.

Selection is marked by **label colour alone** — `greyDarker` against
`greyDarker80` — on top of the background change. The Figma layers also carry a
larger, heavier face on the selected label, but applying it resizes the button
as the selection moves, so the strip jumps under the cursor; every button keeps
one 13.33px/500 face instead.

## Features

### Single Selection

ButtonGroup automatically manages the active state, ensuring only one button can be selected at a time.

### External State Control

You can control the selected item externally using the `value` prop. Pass the
item's `id` — usually what you already have in state — or the whole item:

```tsx
import { useState } from 'react';

function ControlledDemo() {
  const [selectedId, setSelectedId] = useState(items[0].id);

  return (
    <ButtonGroup
      items={items}
      value={selectedId}
      onClick={(item) => setSelectedId(item.id)}
    />
  );
}
```

### Disabled Items

Individual buttons can be disabled by setting `disabled: true` in the item:

```tsx
const itemsWithDisabled: ButtonGroupItem[] = [
  { id: 1, text: 'Available', disabled: false },
  { id: 2, text: 'Disabled', disabled: true },
  { id: 3, text: 'Active', disabled: false },
];
```

### Custom Styling

Apply custom styles to all buttons using the `buttonStyles` prop:

```tsx
import { css } from '@emotion/react';

function StyledDemo() {
  return (
    <ButtonGroup
      items={items}
      onClick={handleClick}
      buttonStyles={css`
        background: white;
        border: 1px solid #ddd;

        &:hover {
          background: #f5f5f5;
        }

        &.active {
          background: #007bff;
          color: white;
        }
      `}
    />
  );
}
```
